Ты — Principal System Architect и Senior Full-Stack Engineer. Твоя задача — спроектировать и разработать с нуля корпоративную систему складского и товарного учета **«Pokiza Core»** для компании **«Pokiza»** (Таджикистан).

# 3. CORE USER FLOW (ПОРУЧЕНИЕ ДИРЕКТОРА — СТРОГОЕ ИСПОЛНЕНИЕ)

### Шаг 1: Поиск по коду / Сканирование штрихкода
На главном экране оператора расположена центральная минималистичная строка ввода/сканирования штрихкода (работает как с аппаратным USB/Bluetooth-сканером в режиме эмуляции клавиатуры, так и при ручном вводе кода).
- Как только штрихкод введен/отсканирован, система мгновенно открывает **Оперативную Карточку Продукта**.
- **Отображение данных в карточке (Пример):**
  - Название: `Вода Хаёт 0.5 литров`
  - Штрихкод / Код: `4870001234567`
  - Текущий остаток в двойном/конвертируемом выражении: **`110 штук / 55 литров`** (или иная настроенная в справочнике пропорция, например объем тары * количество).
  - Динамические характеристики товара (заданные в конструкторе).
  - Две крупные основные кнопки действий: **[ ПРИНЯТЬ (Приход) ]** и **[ ОТПРАВИТЬ (Расход) ]**.

### Шаг 2: Форма операции «Принять» (Inbound) и «Отправить» (Outbound)
При нажатии на кнопку **«Принять»** или **«Отправить»** открывается чистая, сфокусированная форма проведения операции по товару:

1. **Три ключевых селектора/списка:**
   - **Список 1 — Товар:** Выпадающий список с поиском (по умолчанию уже предвыбран товар, из карточки которого перешли, но сотрудник может переключить при необходимости).
   - **Список 2 — Количество (Сколько):** Числовое поле ввода (с быстрыми пресетами или чистым вводом) + автоматический пересчет во вторичную единицу измерения в реальном времени (например, вводим `100 шт` -> рядом сразу пишется `= 50 литров`).
   - **Список 3 — Единица измерения:** Выпадающий список доступных для этого товара единиц измерения из динамического справочника (`шт`, `литр`, `упаковка`, `паллета`, `кг` и т.д.).

2. **Обязательные атрибуты контроля («Сколько, Кто и Когда»):**
   - **Сколько:** Итоговый объем операции в базовой и выбранной единице измерения.
   - **Кто:**
     - *Исполнитель (Сотрудник):* Автоматически подтягивается текущий авторизованный пользователь (ФИО, роль, смена) без возможности подделки.
     - *Контрагент / Получатель / Отправитель:* Выпадающий список из динамического справочника (например: линия производства, склад, водитель, точка сбыта или ответственное лицо).
   - **Когда:** Точная системная дата и время операции (Timestamp с часовым поясом Душанбе `UTC+5`). По умолчанию фиксируется автоматически в момент проведения; при наличии прав (Менеджер/Админ) позволяет указать фактическое время смены/накладной.

3. **Динамические поля операции (из Конструктора):**
   - Любые дополнительные поля, которые Администратор привязал к операции «Принять» или «Отправить» для данной категории товара (например: «Номер партии», «Комментарий», «Номер машины», «Температура/Влажность», «Срок годности»).

При отправке формы остаток товара в БД пересчитывается атомарно внутри SQL-транзакции (при «Отправить» проверяется достаточность остатка, чтобы не уйти в минус, если это запрещено настройками), а запись навсегда сохраняется в журнале движений (`inventory_transactions`).

# 4. СПРАВОЧНИК ТОВАРОВ И 100% ДИНАМИЧЕСКИЙ КОНСТРУКТОР (ADMIN ENGINE)
Ни одно бизнес-свойство не должно быть захардкожено в коде. Администратор управляет системой через раздел **«Конструктор и Справочники»**:

1. **Конструктор Единиц Измерения (`units_of_measure`):**
   - Админ может добавлять, редактировать и скрывать любые единицы измерения (`шт`, `л`, `кг`, `блок`, `паллета`).
   - Настройка формул конвертации для карточки товара: у товара задается Базовая ЕИ (например, `шт`), Вторичная ЕИ для отображения (например, `л`) и коэффициент (например, `1 шт = 0.5 л`). Благодаря этому карточка выводит: `110 штук / 55 литров`.

2. **Конструктор Атрибутов (`attribute_definitions`):**
   - Админ может создавать кастомные поля для:
     a) **Карточки товара** (например: Литраж, Бренд, Тип упаковки, Срок хранения).
     b) **Формы «Принять»** (например: Линия розлива, Номер смены, Поставщик).
     c) **Формы «Отправить»** (например: Получатель/Дистрибьютор, Номер путевого листа).
   - Типы создаваемых полей: `TEXT` (строка), `NUMBER` (число), `SELECT` (выпадающий список с настраиваемыми вариантами), `DATE` (дата/время), `BOOLEAN` (чекбокс Да/Нет).
   - Настройки каждого поля: Обязательное / Необязательное, Значение по умолчанию, Порядок сортировки, Активность.

3. **Конструктор Карточек Товара и Категорий (`products` & `categories`):**
   - При создании товара в Справочнике админ выбирает категорию, задает название, штрихкод (или генерирует внутренний код), выбирает применимые единицы измерения и отмечает галочками, какие динамические атрибуты применимы к этому товару.

4. **Динамические пользовательские списки (`custom_dictionaries`):**
   - Админ может создавать собственные выпадающие списки (например, список цехов, список складов, список контрагентов) и привязывать их к полям типа `SELECT`.

# 5. АРХИТЕКТУРА РЕГИСТРАЦИЙ, ЛОГИНОВ И ИЕРАРХИИ (RBAC)
Это закрытая корпоративная система компании «Pokiza». Публичной саморегистрации с улицы быть не должно — аккаунты создаются по строгой иерархии:

### Ролевая иерархия (Role-Based Access Control):
1. **`SUPER_ADMIN` (IT-отдел / Главный Администратор):**
   - Полный доступ ко всей системе, конструктору таблиц, справочникам, единицам измерения, созданию любых пользователей, настройкам безопасности и полному журналу аудита (`Audit Logs`).
2. **`DIRECTOR` (Директор / Руководство):**
   - Доступ ко всем отчетам в реальном времени, аналитике остатков, истории всех операций «Принять/Отправить» (кто, сколько, когда), просмотру аудита и управлению справочниками.
3. **`MANAGER` (Начальник склада / Старший смены):**
   - Проведение прихода/расхода, создание карточек товаров в справочнике, регистрация линейных сотрудников (`OPERATOR`), корректировка остатков (инвентаризация с обязательным указанием причины).
4. **`OPERATOR` (Сотрудник склада / Оператор):**
   - Максимально простой интерфейс без лишних вкладок: только сканирование штрихкода, просмотр карточки товара и кнопки «Принять» / «Отправить» + история собственных операций за смену.

### Безопасность и Аудит:
- Вход по связке `Логин (или Табельный номер / Телефон) + Пароль`.
- Хеширование паролей через `bcrypt` / `argon2`.
- Таблица `audit_logs`: любое действие в системе (приемка, отправка, изменение карточки товара, добавление новой единицы измерения админом) записывает `user_id`, `action`, `entity_type`, `old_value (JSONB)`, `new_value (JSONB)`, `ip_address`, `created_at`.

# 6. DATABASE SCHEMA BLUEPRINT (POSTGRESQL)
Реализуй следующую структуру таблиц в PostgreSQL:
1. `users` (`id`, `username`, `full_name`, `password_hash`, `role`, `is_active`, `created_by`, `created_at`)
2. `units_of_measure` (`id`, `code`, `name`, `is_active`)
3. `custom_dictionaries` (`id`, `name`, `slug`, `items JSONB`) — для динамических выпадающих списков.
4. `attribute_definitions` (`id`, `target_type` ['PRODUCT', 'TX_INBOUND', 'TX_OUTBOUND'], `key`, `label`, `field_type` ['TEXT', 'NUMBER', 'SELECT', 'DATE', 'BOOLEAN'], `dictionary_id`, `is_required`, `sort_order`, `is_active`)
5. `products` (`id`, `barcode` UNIQUE INDEX, `name`, `sku`, `base_unit_id`, `secondary_unit_id`, `conversion_factor` NUMERIC(12,4), `current_stock_base` NUMERIC(14,4) DEFAULT 0, `enabled_attribute_ids JSONB`, `custom_attributes JSONB`, `is_active`, `created_at`, `updated_at`)
6. `product_allowed_units` (`product_id`, `unit_id`, `multiplier_to_base` NUMERIC(12,4)) — позволяет принимать/отправлять товар как в штуках, так и в литрах или упаковках с автопересчетом в базовый остаток.
7. `inventory_transactions` (`id`, `tx_type` ['INBOUND', 'OUTBOUND', 'ADJUSTMENT'], `product_id`, `quantity_entered` NUMERIC(14,4), `unit_id`, `quantity_base_calculated` NUMERIC(14,4), `performed_by_user_id` [Кто], `counterparty_name` [От кого / Кому], `performed_at` [Когда], `custom_attributes JSONB`, `notes`, `created_at`)
8. `audit_logs` (`id`, `user_id`, `action`, `entity`, `entity_id`, `payload JSONB`, `created_at`)
